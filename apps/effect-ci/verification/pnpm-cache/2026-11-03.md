Every Vite+ task then reported `cache miss: 'node_modules/.modules.yaml' modified`.
Snapshot transport succeeded; task-cache reuse failed.

A disposable checkout reproduced the exact miss while retaining only
`node_modules/.vite/task-cache` across fresh dependency installs. Comparing pnpm's
metadata showed one change: `prunedAt`. Retaining `.modules.yaml` alongside the
task cache produced explicit cache-hit messages for typecheck, lint, and build
across two fresh installs. Changing `src/message.js` then produced explicit source
misses and the updated bundle. No task inputs were excluded or rewritten.

The unlanded fix adds `.modules.yaml` to the existing default transport paths.
The cache identity includes paths, so old snapshots use another namespace.
Custom paths and `cache: false` keep their current contracts. Dependencies still
install against the current checkout. Vite+ remains responsible for invalidation.

`run build --local` with an unusable endpoint succeeded in 1.709 s and returned
`location: local`. Ordinary `run build` with an unusable endpoint returned exit 3
and `CI_REMOTE_TARGET_UNAVAILABLE`; it did not execute the local build.
`AI_AGENT=hosted-pnpm-proof` selected JSON without `--format=json` for both hosted
runs, which returned `ok: true`, `location: remote`, and their distinct IDs.

Process guidance: the host README and SELF-HOST deployment guides own sequence and
credentials. Prior art: the native adapter's existing default task-cache paths,
its path-based cache identity, and its cache-preserving checkout. Vite+ `1.0.0`'s
bundled automatic-data-tracking guide assigns fingerprinting to Vite+; this fix
preserves the real metadata rather than overriding its dependency inputs.

Fresh GitHub workload OIDC and GitHub checks are separate acceptance. These runs
used the existing operator Access session. New repository/enrollment setup is
prepared separately and awaits approval. No claim of fresh GitHub workload proof
or deployment readiness is made here.
