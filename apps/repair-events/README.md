# Authenticated Issue notification capture

Stage-one Generic Webhook receiver, not a repair trigger. POST `/notifications` requires a dedicated 256-bit hex secret in `cf-webhook-auth`. Missing/incorrect/unconfigured secrets reject before body reads. No App/OAuth, AI, Flue, writer, shell, or outbound binding. The public response never returns capture bytes, hashes, secrets, account metadata or storage details. The named evidence reader is private service-only, not an HTTP route.

Bodies are capped at32KiB/5seconds, compressed bodies reject, malformed UTF-8 rejects. Four immutable SQLite capture slots (maximum128KiB raw bodies) deduplicate EXACT BYTES by SHA256 before acknowledging. No reset/delete route. Storage uncertainty/full fails closed. Byte dedupe is NOT semantic incident dedupe: timestamp, formatting or content changes may occupy different slots. `quarantined:true` and `incidentDedupeVerified:false` always remain explicit. No payload data is passed to a model or used as repository/version/repair authority.

The documented exact Notifications test message returns204 without recording an Issue. Only the account-eligible `workers_observability_real_time_issue` alert type with a JSON data object can be captured; a generic `workers_observability_alert` is a different alert and rejects. The precise real-time Issue data schema is not established by the [generic payload documentation](https://developers.cloudflare.com/notifications/reference/webhook-payload-schema/). Capturing an authenticated real delivery privately is a prerequisite to a strict owned source/version/Issue normalizer, not a substitute. See [shared-secret setup](https://developers.cloudflare.com/notifications/get-started/configure-webhooks/).

Not deployed or enrolled yet. Inspect actual policy/destination/automation identities and enable only after receiver readiness. No account-wide alert enrollment. Capture private raw evidence; do not publish diagnostics or relabel a synthetic test as authentic delivery. No fresh inference until real Issue/source/version/base pins and durable incident admission are verified.
