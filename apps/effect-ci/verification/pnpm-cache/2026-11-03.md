## Walkthrough workload proof follow-up

The existing [OIDC workflow](https://github.com/ericclemmons/effect-ci-testbed/blob/6ea26405d920f79d665953fd160b0ec01a0a7316/.github/workflows/oidc-live-proof.yml)
was dispatched with `example=walkthrough`; no new repository was created.
The [first bounded run](https://github.com/ericclemmons/effect-ci-testbed/actions/runs/41763133100)
enrolled this existing repository with GitHub OIDC and passed ordinary remote,
explicit remote, and local tutorial execution. Its deployment job was skipped.
The hosted unknown-goal run ended with `CI_UNKNOWN_TARGET`, but native subscription
events stopped at `step_errored` without a terminal workflow event. The CLI waited
instead of returning. The disposable GitHub job was stopped after confirming the
native terminal status and reproducing the missing event through an independent
subscription.

The CLI fix bounds each subscription, checks the existing status endpoint after
an interrupted stream, and resumes the same run while it is live. It reports a
failure only when status confirms `errored` or `terminated`, retaining received
command diagnostics. It does not infer workflow failure from a step failure or
disconnection. The existing remote CLI test now reproduces this native behavior.
This client fix is implemented but unmerged; no additional host deployment is
needed for the workflow to use its checked-out CLI.
